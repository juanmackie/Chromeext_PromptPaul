# OpenUI parser compatibility experiment

Reviewed 9 October 2026 against the pinned package and the current native answer contract. This is a local parser/format experiment, not a model-quality benchmark. No provider credentials, page data, model generation, or network calls were used by the parser runner.

## Decision

Use Prompt Paul's native version 1 answer envelope for the stage 1 cards. Do not adopt `@openuidev/lang-core` in the extension. The pinned parser works for small summary and comparison examples, but its parser API does not enforce input-byte, nesting-depth, or statement-count limits before parsing. A post-parse projection cannot bound parser work. The native decoder caps the payload at 32 KiB, checks JSON depth before `JSON.parse`, rejects unknown fields and block types, and projects only its small summary/key-value/comparison allowlist.

This follows the accepted proposal's gate, recorded in [REVIEW_PLAN.md](../REVIEW_PLAN.md#2026-10-09-openui-inspired-answer-cards): reuse OpenUI only if its parser accepts enforceable resource limits and materially improves the result. The source review found no such pre-parse controls, and the direct parser observations below confirm that large and high-statement-count inputs are accepted. A custom pre-parser for OpenUI's quoted and escaped DSL would add another parser and validation boundary solely to adopt a format we do not need.

## Fixture results

The same small summary and comparison meanings were represented as OpenUI Lang and as Prompt Paul's `answerSchema.js` version 1 payload. The native prompt measurement uses the actual `ANSWER_CARD_INSTRUCTIONS`; OpenUI uses `generateSystemPrompt()` with a matching small component library and one example. These prompts cover similar component names but are not semantically identical in every instruction, so their byte and rough-token counts are directional format estimates, not an apples-to-apples model benchmark.

| Summary                      | 88 output bytes; parser produced a `Summary` root in 4.1 ms in the final local run. Prompt plus output: 2,760 bytes; roughly 686 tokens at 4 characters/token.            | 263 wire bytes; one validated block in 0.6 ms. Prompt plus output: 1,515 bytes; roughly 379 tokens at 4 characters/token.                        |
| Comparison                   | 102 output bytes; parser produced a `Comparison` root in 4.0 ms. | Malformed / truncated        | Both inputs were flagged `incomplete`, while a partial `Summary` root was still returned. The caller must inspect `meta.incomplete` and keep the Markdown fallback.       | Both unfinished-fence fixtures returned readable fallback text with no cards (`incomplete`). Invalid closed JSON is covered by the schema tests. |

It was not rejected by a pre-parse depth guard.                | A 20-level nested JSON value was rejected by the quoted-string-aware depth scan before `JSON.parse`.                                             |

The result exposes the count only after parsing.                                      | Thirteen blocks exceeded the 12-block allowlist and were rejected.                                                                               |

The token figures above are only a rough `characters / 4` conversion of the recorded prompt and output strings. They are not tokenizer output or measured model tokens, and no model-generation costs or rates were tested. Parser timings are single local measurements from the runner, without package import or browser rendering time; they are not performance guarantees. The full per-case records are generated by the ignored runner below.

## Reproduction

Run `node plans/openui-experiment/run-parser-experiment.cjs` from this working tree. It uses the locally retained ignored 0.3.2 tarball, extracts the package to the OS temp directory, runs each OpenUI case in a child process with a five-second ceiling, imports the current native `src/utils/answerSchema.js`, and writes bounded fixture metrics to ignored `metrics.json`. These ignored assets are local experiment artifacts, so they are absent from clean clones. Recreate the tarball with install scripts disabled and telemetry off: set `npm_config_ignore_scripts=true`, `npm_config_audit=false`, `npm_config_fund=false`, `OPENUI_TELEMETRY_DISABLED=1`, and `DO_NOT_TRACK=1`, then run `npm pack @openuidev/lang-core@0.3.2 --ignore-scripts --pack-destination plans/openui-experiment`.

The native contract was measured against the local production module, not a duplicate parser. Browser behavior is covered separately in [`answer-cards.spec.js`](../tests/browser/answer-cards.spec.js); the local scripted provider validates delivery and fallback, not live model task quality.
