# Browser Tests DOX

## Purpose

`tests/browser/` provides page-agent-style Playwright coverage against the unpacked Prompt Paul extension in a real Chromium-family browser.

## Ownership

- `page-actions.spec.js` owns the page-action integration cases, including the model-free autocomplete bridge selection (typed suggestion chosen through `directAction` with the benchmark grader as oracle), the Gmail sort agreement check (the opened menu option resolves to the same control in the outline and the dispatch map), approved link navigation, owned-tab link opening, hostile content-script message rejection, and trusted precise-input preparation/finalization against a local fixture, plus the opt-in background debugger path after the site policy approves it. It also covers invalid-field and live-region evidence: a non-sensitive invalid control discloses bounded `aria-errormessage` text, a sensitive invalid control keeps only the invalid flag (no error attribute), and bounded `alert`/`status` notices appear in the snapshot and outline.
- `page-action-evaluation.spec.js` owns real-browser executor-regression coverage of browser-safe corpus cases, bounded receipt/failure/action/tool-argument metrics, live snapshot scope/diff measurement, distinct measured injection-fixture execution (`injection-hidden.html`, `injection-alt.html`, `injection-aria.html`), measured denial outcomes, and a browser-level metric gate that fails when an injection/sabotage fixture is missed or a denied action is recorded as delivered. Restricted-page and Hermes provider boundaries remain in the unit evaluation matrix.
- `approval-recovery.spec.js` owns real-browser approval sequencing and reconnect/checkpoint recovery coverage: approval decisions bind to the current confirmation, run, owner token, and source tab (wrong bindings are rejected without consuming the confirmation), approved harmless input executes exactly once with a verified receipt backed by the fixture's actual value, denial and confirmation timeout and Stop leave the page unchanged and consumed decisions cannot be replayed, model checklists never change consent and explicit run approval cannot cover high-risk Send (a stale snapshot after a verified mutation must re-inspect before acting), startup renders the existing reconnect controls, Watch adopts the active run without a second provider request, a run completing during reconnect produces no duplicate output or stale controls, and checkpoint Resume requires an explicit user action plus a fresh inspection and never replays automatically — the Resume test asserts the fresh-inspection contract at the wire: the resumed run's provider request contains a fresh matching synthetic `page_get_state` call/result pair with automatic tool selection, and the interrupted mutation remains untouched.
- `act-settings.spec.js` owns saved origin trust, high-risk site confirmations, Options block/remove, run-start policy snapshots, blocked redirect refusal, expired-card transport races and model-support warnings. It uses only local simulated models; no provider generation occurs during enable/settings checks.
- `options-feedback.spec.js` owns real-browser Options status-feedback coverage: skill-form validation and success messages render as visible toasts (guarding the Bootstrap `.toast:not(.show){display:none}` cascade regression that hid every `showStatus()` message) while Bootstrap's own `#statusToast` stays hidden, and a saved skill appears in the skills table.
- `options-unsaved.spec.js` owns per-section Options state and the benchmark's Codex setup integration: a mocked device-code sign-in uses the existing Options flow, resolves a supported model/reasoning level, and keeps tokens out of profile records.
- `chat-actions.spec.js` owns real-browser selected-text chat action and sidebar model-status coverage; its recapture flow follows the active tab after the sticky selection is detached.
- `selected-text.spec.js` owns real-browser selected-text capture and delivery coverage: a queued background-tab selection attaches to the composer tray with zero provider requests and survives tab changes, Analyze delivers the structured `selected_text` context into the submitted request (asserted against the mocked provider) and renders the mocked reply, a handoff queued while no panel exists is consumed on panel load, and after detaching the selection the live recapture follows the newly active tab.
- `document-drop.spec.js` owns real-browser document-drop coverage: dropped text documents attach to the composer tray with zero network activity — asserted both at the page wrapper and at the fixture server (`fixtureServer.mockRequests()` must stay empty, closing the service-worker path) — truncation marking, removal, the explicit Replace/Keep-current choice for a second document, the single-document limit message, invalid/oversized handling, send-through-`document`-context with failed-submission retention, Retry/Edit identity replay, the empty-prompt document instruction fallback, and the combined media + pending-document send (a media drop auto-analyze must carry the pending document as structured context and clear the chip on terminal success; asserted against the recorded mock-provider request body).
- `acceptance-journeys.spec.js` owns six concrete acceptance journeys for real-browser regression (summarize an article with attached context, rewrite selected text retaining surroundings, follow up on an attached document, filter a table and report matching rows, fill a harmless form under approval, and compare two pages opened explicitly). Online-model text generation is separated out of the scripted gate: the deterministic context/test/approval parts are asserted credential-free, and the natural-language bubble assertions are commented out and trailed separately with a live provider.
- `notch.spec.js` owns browser-page notch enablement, isolation, accessibility state, horizontal dragging and remembered position, pinned prompt rendering, Act controls, activity glow, selection gating, live disable coverage, and the user-gesture-bound All actions handoff.
- `theme.spec.js` owns Light/Dark/System selector coverage and live system-preference changes.
- `answer-cards.spec.js` owns the explicit composer card flow through a local scripted provider, safe summary/key-value/comparison rendering, progressive block/focus/scroll stability, terminal/Stop fallback, local sort/filter/reset without requests, original-context follow-up prefill and Send, narrow layouts and keyboard access. Its local replies measure UI delivery, not model quality.
- `worker-lifecycle.spec.js` verifies that a clarification stays answerable after 40 seconds without worker messages and that the worker shuts down normally after completion. `uninspectedBrowserSupport.js` drives browser/page targets through Playwright's bundled WebSocket transport without attaching to the service worker; ordinary Playwright worker inspection would hide idle shutdown. The two bounded absence windows test the real Chrome idle timer and must not poll the worker.
- `browserTestSupport.js` owns browser launch, fixture-server, extension-worker, test cleanup helpers, optional development-trace capture, and the mocked OpenAI-style chat-completions endpoint (`/mock-chat`) that records bounded requests (Authorization presence only, never credential values) and answers with a deterministic SSE reply for credential-free delivery tests. The fixture server answers only regular files beneath `fixtures/` (directory, missing, and traversal-shaped paths return 404) so a stray navigation can never crash a run. The extension harness exposes evaluation-task events/results and bounded confirmation/progress counts to `scripts/act-benchmark.js`; direct page-action test calls inject `content_script_page_actions.js` on demand to match the production bridge lifecycle. Local `/models` advertises simulated capability records; `/act-site-redirect` redirects only to the same local fixture server under its localhost origin.
- `extension-harness.html` and `extension-harness.js` own the extension-page bridge used by tests.
- `fixtures/` owns credential-free local representatives of form and compose pages, including `act-precise-input.html` for trusted input delivery, `act-frame-host.html`/`act-frame-child.html`/`act-frame-payment.html` for frame routing and payment-frame exclusion, and distinct injection fixtures (`injection-hidden.html`, `injection-alt.html`, `injection-aria.html`) for hidden/alt/ARIA trust-boundary scenarios, the acceptance-journey fixtures (`article.html`, `notes.md`, `plan-a.html`, `plan-b.html`, `tables.html`), and `act-benchmark.html`, whose query-selected cases cover SPA menus, autocomplete, custom radio/dropdown, open shadow DOM, same-origin iframe, modal dismissal, pagination, infinite scroll, long-page text, and duplicate row actions.

## Local Contracts

- The suite must load the repository unpacked, exercise the content-script bridge and indexed semantic controls, and remain safe to run without network credentials. The separate `npm run benchmark:act -- --run` is explicitly opt-in, uses only local fixtures, accepts an API environment key or a manually completed Codex sign-in in its dedicated ignored profile, and is not part of the browser regression suite or CI.
- Coverage includes connection interruption, compose contenteditable fields, executor timeout, same-tab and cross-origin link navigation under Act, current-tab `_blank` navigation, explicit foreground and background owned-tab opening with readiness, active-tab navigation recovery, tab-local failure handling, service-worker restart, manual-intervention resume, verified/unverified receipts, and live scope/diff measurements.
- Hidden-tab settlement coverage disables Playwright's focus/visibility overrides and creates an explicitly inactive target in the harness window. It asserts the target is actually hidden and verifies input receipts, scrolling, and a subsequent healthy bridge inspection against `act-hidden-settle.html`. Worker lifecycle coverage still uses `uninspectedBrowserSupport.js` and never attaches to the worker.
- `launchTestBrowser(..., {realVisibility: true})` disables Playwright's default CDP overrides for benchmark/oracle cases; ordinary browser regressions keep their existing defaults. The ten roadmap fixture graders are checked against idle, oracle, and wrong outcomes, including redundant prefilled edits and synthetic-versus-trusted Enter.
- Branded-browser runs select Chrome or Edge with `PROMPT_PAUL_BROWSER=chrome|edge`; the suite uses the browser-level CDP `Extensions.loadUnpacked` path required by Chrome 137+ and equivalent Edge builds. The default uses the installed Playwright Chromium runtime. `PROMPT_PAUL_BROWSER_EXECUTABLE` points at any installed Chrome/Edge binary and is the fallback when the Playwright browser download is unavailable (for example on a network that cannot reach the Playwright CDN); the full suite passes on installed Chrome.
- Teardown must never fail a passing test: the branded path kills the browser with `taskkill` after `browser.close()`, which usually exits it first, so that call is best effort. Likewise a failed `openHarness` closes its own context, because callers invoke it before their `try/finally` and a leak would starve later launches.

## Work Guidance

- Keep browser tests headed by default because extension service workers are unavailable in legacy headless Chromium.
- Use local fixtures instead of Gmail/Outlook accounts or private data.
- Use deterministic waits (selector/run-state/polling) instead of fixed sleeps. The one sanctioned exception is a bounded absence window that asserts something does NOT happen when no event exists to await (e.g., the Resume no-auto-replay check in `approval-recovery.spec.js`); mark it with an explanatory comment.
- Keep evaluation output limited to result, receipt disposition, postcondition evidence, failure code, action count, prompt size, and bounded scope metrics. The evaluation matrix uses its measured 180-second test timeout so credential-free cases do not fail from the default per-test budget; cleanup remains bounded.
- Keep the harness limited to test observability and existing runtime message contracts; do not add production capabilities for test convenience.
- Set `PROMPT_PAUL_CAPTURE_DIAGNOSTICS=true` to enable the development trace for each browser test and write per-test service-worker records to `PROMPT_PAUL_DIAGNOSTICS_DIR` (default `artifacts/browser-diagnostics/`). Keep this mode local and review records before sharing them.

- Phase 2 cases reproduce viewport text loss, unstable IDs, omitted values, unsupported scalar/append controls, shadow roots, custom selects, nested scrolling and undeclared receipt evidence. Removed-node tests require stale state and fresh inspection; focused no-effect controls isolate unverified delivery from focus-change evidence. The safe-value journey also checks that focused metadata does not duplicate the field value.

## Verification

- Adaptive settlement uses `act-adaptive-settle.html` to verify an action-triggered busy result while an unrelated spinner remains present; assert returned snapshot content and settlement timing.
- Phase 1 fixtures cover keyboard/focus identity and Send confirmation, label-backed hidden toggles, semantic widget roles, double-click and hover. The local mock provider can reject named tool choice; assert the first request carries a compact snapshot and record only before/after byte counts as measurement artifacts.
- Provider fixtures seeded immediately after install must wait for the Options starter-profile write before replacing storage, so bootstrap cannot overwrite the test connection.

- Run `npm run test:browser` from the repository root; the command runs every spec in this directory.
- Run `npx prettier --check` and `npx eslint` for changed browser test files.
